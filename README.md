# Cashback Merge

Игра в духе 2048 с плитками кэшбэка и конфигурацией промокампании.

Допустимые уровни плиток: `1%`, `2%`, `4%`, `8%`, `16%`, `32%`.

## Текущий этап

Реализованы MR1 и MR2:

- неизменяемая модель поля и состояния партии;
- загрузка JSON-конфигурации с проверкой структуры и бизнес-правил;
- начальное поле с двумя плитками в разных клетках;
- воспроизводимая инициализация по seed;
- взвешенный выбор значения плитки по вероятностям кампании;
- текстовый вывод поля, счёта и использованных ходов;
- сдвиг и однократное слияние плиток в четырёх направлениях;
- начисление score, учёт валидных ходов и определение завершения партии;
- сессия с одним генератором случайных чисел на всю партию;
- CLI: `init`, интерактивная игра `play`, воспроизведение `replay`;
- обязательные тесты MR1/MR2 и ограниченные по объёму генеративные проверки.

**Бонус MR1**: размер поля задаётся через конфигурацию.

**Бонусы MR2**:
1. генеративные проверки слияния
2. воспроизведение партии по seed и списку ходов.

Расчёт наград, симуляция и отчёты относятся к MR3. Взвешенное появление плиток подготовлено заранее в MR1.

## Требования

- JDK 25 или новее.
- Gradle устанавливать отдельно не требуется: используется Gradle Wrapper.

Все команды выполняются из корня проекта.

## Запуск

### Windows PowerShell

Создать начальное поле с указанным seed:

```powershell
.\gradlew.bat run --args="init --config config/campaign.example.json --seed 42"
```

Создать поле со случайным seed:

```powershell
.\gradlew.bat run --args="init --config config/campaign.example.json"
```

В командах `init` и `play` выбранный seed печатается в первой строке.
Для воспроизведения нужно использовать тот же конфиг, seed и последовательность попыток ходов.

Seed принимается как `long`, ноль и отрицательные значения допустимы.

Показать справку и версию:

```powershell
.\gradlew.bat run --args="--help"
.\gradlew.bat run --args="init --help"
.\gradlew.bat run --args="play --help"
.\gradlew.bat run --args="replay --help"
.\gradlew.bat run --args="--version"
```

Запуск без аргументов также показывает справку.

### Интерактивная партия

Игра на поле `4x4` с заданным seed:

```powershell
.\gradlew.bat run --args="play --config config/campaign.example.json --seed 42"
```

Игра на поле `5x5`:

```powershell
.\gradlew.bat run --args="play --config config/campaign.5x5.example.json --seed 42"
```

Без `--seed` выбирается случайный seed:

```powershell
.\gradlew.bat run --args="play --config config/campaign.example.json"
```

Вводи по одной команде на строку: `UP`, `DOWN`, `LEFT`, `RIGHT`.
Регистр и пробелы по краям не влияют на разбор.
`QUIT` или конец стандартного ввода останавливают игру с выводом результата.
Пустые строки игнорируются. Неизвестная команда выводит ошибку и позволяет продолжить ввод.

Финальный блок содержит seed и строку `Ходы для replay`.
В список попадают распознанные попытки направлений, включая ходы без изменения поля.
Неизвестный текст, пустые строки и `QUIT` в список не входят.

### Воспроизведение партии - бонус MR2

Передай seed и список попыток через запятую:

```powershell
.\gradlew.bat run --args="replay --config config/campaign.example.json --seed 42 --moves RIGHT,LEFT,DOWN,UP"
.\gradlew.bat run --args="replay --config config/campaign.5x5.example.json --seed 42 --moves RIGHT,LEFT,DOWN,UP"
```

В `replay` seed обязателен. Направления допускают любой регистр и пробелы по краям.
Пустые элементы и неизвестные направления отклоняются до запуска партии.
Для пустого списка ходов опусти `--moves`:

```powershell
.\gradlew.bat run --args="replay --config config/campaign.example.json --seed 42"
```

Короткий список восстанавливает промежуточное состояние.
Попытки после завершения партии игнорируются; итоговая строка содержит переданный список для повторного replay.
Воспроизводимость предполагает одинаковый конфиг и ту же версию реализации.

## Правила партии

- Изначально появляются две плитки в разных клетках.
- Ход сначала сдвигает плитки и объединяет равные соседние значения.
- Каждая исходная плитка участвует максимум в одном слиянии за ход.
- Плитки `32%` не объединяются. Само достижение `32%` не завершает партию.
- Ход, изменивший поле, расходует один ход и создаёт ровно одну новую плитку, включая последний разрешённый ход.
- Ход без изменения поля сохраняет состояние и последовательность RNG.
- Партия завершается при достижении лимита или отсутствии доступных ходов.
  При одновременном выполнении условий приоритет имеет лимит.
- Score увеличивается на сумму значений созданных слияниями плиток.
  Например, `[2,2,4,4] -> [4,8,.,.]` даёт `4 + 8 = 12` очков до появления новой плитки.
- Сдвиги без слияний и появление плитки не начисляют очков.
- Переполнение накопленного score обнаруживается до обращения к RNG.

Таблица `rewardTable` задаёт итоговую денежную награду; её применение реализуется в MR3.

## Конфигурация кампании

Примеры:

- [Базовая кампания 4x4](config/campaign.example.json).
- [Кампания 5x5](config/campaign.5x5.example.json).

| Поле | Формат | Назначение |
|---|---|---|
| `boardSize` | Целое JSON-число | Размер квадратного поля, не меньше 2 |
| `movesLimit` | Целое JSON-число | Положительный лимит ходов |
| `spawnRules` | Массив объектов | Уровни появляющихся плиток и их вероятности |
| `rewardTable` | Массив объектов | Пороги кэшбэка и соответствующие награды |
| `maxRewardCashback` | Строка с целым числом | Уровень последнего порога наград |
| `maxRewardAllowedRate` | Строка с десятичным числом | Допустимая доля максимальных наград, от 0 до 1 |

Все поля таблицы обязательны. Необязательное служебное поле `_note` допускается и игнорируется.

Пример правила появления:

```json
{ "cashback": "1", "probability": "0.85" }
```

Это означает появление плитки `1%` с вероятностью `85%`.

Уровни кэшбэка записываются строками без знака `%`.
Вероятности и суммы наград также записываются строками.

### Проверки конфигурации

- Размер поля не меньше 2, лимит ходов положительный.
- Допустимы только уровни кэшбэка `1`, `2`, `4`, `8`, `16`, `32`.
- Spawn-правила не пусты и не содержат повторяющихся уровней.
- Каждая вероятность находится в диапазоне `[0, 1]`.
- Сумма вероятностей равна ровно `1`.
- Таблица наград не пуста, пороги кэшбэка уникальны.
- Суммы наград неотрицательны и не уменьшаются с ростом порога.
- `maxRewardCashback` совпадает с последним порогом наград.
- При нескольких порогах последняя награда строго выше предыдущей.
- `maxRewardAllowedRate` находится в диапазоне `[0, 1]`.

Загрузчик отклоняет отсутствующие поля, неправильные типы,
неизвестные поля, дублирующиеся JSON-ключи и дополнительные данные после корневого объекта.

Поля наград уже загружаются и проверяются; применение наград и проверка допустимой доли игроков относятся к MR3.

## Принятые решения

- `Board` и `GameState` неизменяемы. Добавление плитки создаёт новое поле.
- Координаты начинаются с нуля; строка и столбец находятся в границах поля.
- В одной клетке может находиться только одна плитка.
- Вероятности и денежные суммы представлены `BigDecimal`.
- Целые веса появления плиток представлены `BigInteger`.
- `float` и `double` для вероятностей и денег не используются.
- Свободная клетка выбирается равновероятно.
- Значение плитки выбирается по накопленным точным весам с отбрасыванием случайных значений вне допустимого диапазона.
- Генератор случайных чисел передаётся в `TileSpawner` извне.
- Без `--seed` команды `init` и `play` выбирают случайный seed и выводят его.
- `replay` требует явный seed.
- Одинаковые конфиг, seed и попытки ходов воспроизводят состояние партии в текущей версии реализации.
- Один RNG непрерывно используется для начальных плиток и последующих валидных ходов.
- CLI проверяет аргументы до выполнения команды; интерактивный ввод передаётся через `Reader`.
- Счёт хранится в `long`.
- Ошибки конфигурации обнаруживаются до вывода начального поля.

## Структура кода

Основной пакет: `academy.cashbackmerge`.

| Пакет или класс | Ответственность |
|---|---|
| `model` | Значения плиток, координаты, поле и состояние партии |
| `config` | Конфигурация, JSON-загрузка и валидация |
| `engine` | Инициализация, сдвиги, слияния, выполнение ходов, сессия и replay |
| `presentation` | Текстовое представление состояния и итога партии |
| `cli` | Команды и параметры запуска |
| `Main` | Создание CLI, обработка ошибок и завершение приложения |

## Ошибки и вывод

Состояние партии и справка выводятся в `stdout`.
Ошибки и сообщения журнала направляются в `stderr`.

Коды завершения Java-приложения:

| Код | Значение |
|---:|---|
| `0` | Успешное выполнение, справка или версия |
| `1` | Неожиданная ошибка выполнения |
| `2` | Некорректные аргументы или конфигурация |


При запуске через Gradle ошибка приложения также приводит к неуспешному выполнению задачи `run`.

## Проверка проекта

Форматирование и проверки:

```powershell
.\gradlew.bat spotlessApply check
```

Полная проверка, соответствующая CI:

```powershell
.\gradlew.bat --continue assemble check printCoverage --console=plain
```

Для Linux и macOS:

```bash
./gradlew --continue assemble check printCoverage --console=plain
```


Тесты проверяют модель, конфигурацию, JSON-загрузку, границы весовых интервалов,
слияния, движок, сессии, форматирование и CLI.

Генеративные проверки охватывают все 2401 линии длиной четыре,
192 сгенерированных поля размеров 2, 4 и 5, а также несколько seed.
Проверяются сохранение суммы плиток, однократность слияния,
прибавка к score и симметрия направлений.
Тесты CLI проверяют совпадение итогов `play` и `replay`, ошибки ввода,
случайный seed, конец ввода, завершение партии и поля другого размера.

Обязательные тесты MR1/MR2 включены, кроме воспроизводимости отчёта симуляции из `SeedTest`, которая реализуется в MR3 вместе с пятью обязательными тестами MR3.
