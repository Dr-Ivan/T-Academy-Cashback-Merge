# Cashback Merge

Игра в духе 2048 с плитками кэшбэка и конфигурацией промокампании.

Допустимые уровни плиток: `1%`, `2%`, `4%`, `8%`, `16%`, `32%`.

## Текущий этап

Реализованы MR1, MR2 и MR3:

- неизменяемая модель поля и состояния партии;
- загрузка JSON-конфигурации с проверкой структуры и бизнес-правил;
- начальное поле с двумя плитками в разных клетках;
- воспроизводимая инициализация по seed;
- взвешенный выбор значения плитки по вероятностям кампании;
- текстовый вывод поля, счёта и использованных ходов;
- сдвиг и однократное слияние плиток в четырёх направлениях;
- начисление score, учёт валидных ходов и определение завершения партии;
- сессия с одним генератором случайных чисел на всю партию;
- расчёт денежной награды по максимальной плитке и таблице кампании;
- стратегии `random` и `greedy-score`, симуляции и сравнение кампаний;
- отчёты Markdown и HTML с проверкой допустимой доли максимальных наград;
- CLI: `init`, `play`, `replay`, `simulate` и `compare`;
- все обязательные тесты MR1/MR2/MR3 и ограниченные по объёму генеративные проверки.

**Бонус MR1**: размер поля задаётся через конфигурацию.

**Бонусы MR2**:

1. генеративные проверки слияния
2. воспроизведение партии по seed и списку ходов.

**Бонусы MR3**:

1. стратегия `greedy-score`;
2. сравнение нескольких кампаний;
3. HTML-отчёт.

Взвешенное появление плиток подготовлено заранее в MR1.

## Требования

- JDK 25 или новее.
- Gradle устанавливать отдельно не требуется: используется Gradle Wrapper.

Все команды выполняются из корня проекта.

## Запуск

### Windows PowerShell

Создать начальное поле с указанным seed:

```powershell
.\gradlew.bat run --args="init --config config/campaign.example.json --seed 42"
```

Создать поле со случайным seed:

```powershell
.\gradlew.bat run --args="init --config config/campaign.example.json"
```

В командах `init`, `play`, `simulate` и `compare` параметр `--seed` необязателен.
Выбранный seed печатается в первой строке вывода приложения, а при симуляции также сохраняется в отчёте.
Для воспроизведения партии нужны тот же конфиг, seed и последовательность попыток ходов.

Seed принимается как `long`, ноль и отрицательные значения допустимы.

Показать справку и версию:

```powershell

.\gradlew.bat run --args="play --help"
.\gradlew.bat run --args="replay --help"
.\gradlew.bat run --args="simulate --help"
.\gradlew.bat run --args="compare --help"
.\gradlew.bat run --args="--version"
```

Запуск без аргументов также показывает справку.

### Интерактивная партия

Игра на поле `4x4` с заданным seed:

```powershell
.\gradlew.bat run --args="play --config config/campaign.example.json --seed 42"
```

Игра на поле `5x5`:

```powershell
.\gradlew.bat run --args="play --config config/campaign.5x5.example.json --seed 42"
```

Без `--seed` выбирается случайный seed:

```powershell
.\gradlew.bat run --args="play --config config/campaign.example.json"
```

Вводи по одной команде на строку: `UP`, `DOWN`, `LEFT`, `RIGHT`.
Регистр и пробелы по краям не влияют на разбор.
`QUIT` или конец стандартного ввода останавливают игру с выводом результата.
Пустые строки игнорируются. Неизвестная команда выводит ошибку и позволяет продолжить ввод.

Финальный блок содержит seed, score, максимальную плитку, награду и строку `Ходы для replay`.
Завершённая партия показывает «Итоговую награду», незавершённая — «Награду по текущему полю».
В список попадают распознанные попытки направлений, включая ходы без изменения поля.
Неизвестный текст, пустые строки и `QUIT` в список не входят.

### Воспроизведение партии - бонус MR2

Передай seed и список попыток через запятую:

```powershell
.\gradlew.bat run --args="replay --config config/campaign.example.json --seed 42 --moves RIGHT,LEFT,DOWN,UP"
.\gradlew.bat run --args="replay --config config/campaign.5x5.example.json --seed 42 --moves RIGHT,LEFT,DOWN,UP"
```

В `replay` seed обязателен. Направления допускают любой регистр и пробелы по краям.
Пустые элементы и неизвестные направления отклоняются до запуска партии.
Для пустого списка ходов опусти `--moves`:

```powershell
.\gradlew.bat run --args="replay --config config/campaign.example.json --seed 42"
```

Короткий список восстанавливает промежуточное состояние.
Попытки после завершения партии игнорируются; итоговая строка содержит переданный список для повторного replay.
Воспроизводимость предполагает одинаковый конфиг и ту же версию реализации.

### Симуляция кампании

Все отчёты в примерах записываются в `build/reports/campaigns/`, потому что каталог `build` игнорируется Git.
При запуске команды можно указать любой другой каталог для сохранения отчета.
Каталог назначения должен существовать:

```powershell
New-Item -ItemType Directory -Force build/reports/campaigns | Out-Null
```

Стратегия `random`, 10 000 игроков, заданный seed и Markdown:

```powershell
.\gradlew.bat run --args="simulate --config config/campaign.example.json --players 10000 --seed 42 --strategy random --output build/reports/campaigns/random-4x4.md"
.\gradlew.bat run --args="simulate --config config/campaign.5x5.example.json --players 10000 --seed 42 --strategy random --output build/reports/campaigns/random-5x5.md"
```

Стратегия `greedy-score` и HTML:

```powershell
.\gradlew.bat run --args="simulate --config config/campaign.example.json --players 10000 --seed 42 --strategy greedy-score --output build/reports/campaigns/greedy-4x4.html"
.\gradlew.bat run --args="simulate --config config/campaign.5x5.example.json --players 10000 --seed 42 --strategy greedy-score --output build/reports/campaigns/greedy-5x5.html"
```

Случайный seed и стратегия `random` по умолчанию:

```powershell
.\gradlew.bat run --args="simulate --config config/campaign.example.json --players 10000 --output build/reports/campaigns/random-seed.md"
```

Обязательны `--config`, `--players` и `--output`.
Число игроков должно быть положительным. Формат определяется расширением `.md` или `.html`
без учёта регистра. Существующий отчёт заменяется после расчёта.
Поддерживаются обе стратегии с любым из двух форматов.

- `random` равновероятно выбирает среди ходов, изменяющих поле.
- `greedy-score` выбирает наибольшую немедленную прибавку к score до появления новой плитки.
  При равенстве действует порядок `UP`, `DOWN`, `LEFT`, `RIGHT`.

Имена стратегий принимаются без учёта регистра и пробелов по краям.

Отчёт содержит число игроков, размер поля, лимит ходов, seed, стратегию,
суммарный, средний и максимальный score, распределения максимальных плиток и наград,
число и долю максимальных выплат, допустимую долю, статус и параметры кампании.

```text
actualMaxRewardRate <= maxRewardAllowedRate -> OK
actualMaxRewardRate > maxRewardAllowedRate  -> FAILED
```

Доли записываются от `0` до `1`: `0.20` означает `20%`.
Статус рассчитывается по точному сравнению числа максимальных выплат
с `players * maxRewardAllowedRate`.
Средние и доли округляются до шести знаков методом `HALF_UP` только при выводе,
незначащие завершающие нули убираются.

Это эмпирическая проверка конкретных конфигурации, seed, числа игроков и стратегии.
Она не является математической гарантией для всех возможных партий.
`FAILED` означает превышение бизнес-ограничения; успешное сохранение такого отчёта
даёт код завершения `0`.

### Сравнение кампаний

Повтори `--config` для каждой кампании, минимум два разных файла:

```powershell
.\gradlew.bat run --args="compare --config config/campaign.example.json --config config/campaign.5x5.example.json --players 10000 --seed 42 --strategy random --output build/reports/campaigns/comparison-random.md"
.\gradlew.bat run --args="compare --config config/campaign.example.json --config config/campaign.5x5.example.json --players 10000 --seed 42 --strategy greedy-score --output build/reports/campaigns/comparison-greedy.html"
```

Без `--seed` выбирается одно случайное значение для всего сравнения:

```powershell
.\gradlew.bat run --args="compare --config config/campaign.example.json --config config/campaign.5x5.example.json --players 10000 --strategy random --output build/reports/campaigns/comparison-random-seed.md"
```

`--players` задаёт число игроков в каждой кампании; seed и стратегия общие.
Все конфигурации проверяются до начала симуляций. Повтор одного файла
и совпадение отчёта с любой конфигурацией отклоняются.
Названия кампаний берутся из нормализованных переданных путей и сортируются:
одноимённые файлы из разных каталогов различаются.

Каждый игрок получает одинаковые начальные seed игры и стратегии во всех кампаниях.
Различия конфигураций могут приводить к разным полям и партиям.
Общий отчёт содержит сводную таблицу и подробные результаты каждой кампании.

Примеры отличаются и размером поля, и лимитом ходов: `4x4 / 100` и `5x5 / 30`.
Это сравнение кампаний в целом.

## Правила партии

- Изначально появляются две плитки в разных клетках.
- Ход сначала сдвигает плитки и объединяет равные соседние значения.
- Каждая исходная плитка участвует максимум в одном слиянии за ход.
- Плитки `32%` не объединяются. Само достижение `32%` не завершает партию.
- Ход, изменивший поле, расходует один ход и создаёт ровно одну новую плитку, включая последний разрешённый ход.
- Ход без изменения поля сохраняет состояние и последовательность RNG.
- Партия завершается при достижении лимита или отсутствии доступных ходов.
  При одновременном выполнении условий приоритет имеет лимит.
- Score увеличивается на сумму значений созданных слияниями плиток.
  Например, `[2,2,4,4] -> [4,8,.,.]` даёт `4 + 8 = 12` очков до появления новой плитки.
- Сдвиги без слияний и появление плитки не начисляют очков.
- Переполнение накопленного score обнаруживается до обращения к RNG.

Таблица `rewardTable` задаёт денежную награду по наибольшему достигнутому порогу кэшбэка.
Ниже первого порога награда равна нулю, выше последнего - последней награде.
Несколько максимальных плиток дают одну награду за партию.
Награды плиток не суммируются и не добавляются к score.

## Конфигурация кампании

Примеры:

- [Базовая кампания 4x4](config/campaign.example.json).
- [Кампания 5x5](config/campaign.5x5.example.json).

| Поле | Формат | Назначение |
|---|---|---|
| `boardSize` | Целое JSON-число | Размер квадратного поля, не меньше 2 |
| `movesLimit` | Целое JSON-число | Положительный лимит ходов |
| `spawnRules` | Массив объектов | Уровни появляющихся плиток и их вероятности |
| `rewardTable` | Массив объектов | Пороги кэшбэка и соответствующие награды |
| `maxRewardCashback` | Строка с целым числом | Уровень последнего порога наград |
| `maxRewardAllowedRate` | Строка с десятичным числом | Допустимая доля максимальных наград, от 0 до 1 |

Все поля таблицы обязательны. Необязательное служебное поле `_note` допускается и игнорируется.

Пример правила появления:

```json
{ "cashback": "1", "probability": "0.85" }
```

Это означает появление плитки `1%` с вероятностью `85%`.

Уровни кэшбэка записываются строками без знака `%`.
Вероятности и суммы наград также записываются строками.

### Проверки конфигурации

- Размер поля не меньше 2, лимит ходов положительный.
- Допустимы только уровни кэшбэка `1`, `2`, `4`, `8`, `16`, `32`.
- Spawn-правила не пусты и не содержат повторяющихся уровней.
- Каждая вероятность находится в диапазоне `[0, 1]`.
- Сумма вероятностей равна ровно `1`.
- Таблица наград не пуста, пороги кэшбэка уникальны.
- Суммы наград неотрицательны и не уменьшаются с ростом порога.
- `maxRewardCashback` совпадает с последним порогом наград.
- При нескольких порогах последняя награда строго выше предыдущей.
- `maxRewardAllowedRate` находится в диапазоне `[0, 1]`.

Загрузчик отклоняет отсутствующие поля, неправильные типы,
неизвестные поля, дублирующиеся JSON-ключи и дополнительные данные после корневого объекта.

Симуляция учитывает число игроков, получивших последнюю награду таблицы,
и проверяет их долю по `maxRewardAllowedRate`.

## Принятые решения

- `Board` и `GameState` неизменяемы. Добавление плитки создаёт новое поле.
- Координаты начинаются с нуля; строка и столбец находятся в границах поля.
- В одной клетке может находиться только одна плитка.
- Вероятности и денежные суммы представлены `BigDecimal`.
- Целые веса появления плиток представлены `BigInteger`.
- `float` и `double` для вероятностей и денег не используются.
- Свободная клетка выбирается равновероятно.
- Значение плитки выбирается по накопленным точным весам с отбрасыванием случайных значений вне допустимого диапазона.
- Генератор случайных чисел передаётся в `TileSpawner` извне.
- Без `--seed` команды `init`, `play`, `simulate` и `compare` выбирают случайный seed и выводят его.
- `replay` требует явный seed.
- Одинаковые конфиг, seed и попытки ходов воспроизводят состояние партии в текущей версии реализации.
- Один RNG непрерывно используется для начальных плиток и последующих валидных ходов.
- CLI проверяет аргументы до выполнения команды; интерактивный ввод передаётся через `Reader`.
- Seed симуляции задаёт последовательность seed отдельных игроков.
  Для плиток и выбора ходов используются отдельные RNG;
  длительность партии не меняет seed следующих игроков.
- Счёт партии хранится в `long`, сумма score по игрокам — в `BigInteger`.
- Отчёты не содержат времени генерации; распределения сортируются по значениям.
- Ошибки конфигурации обнаруживаются до вывода начального поля.

## Ошибки и вывод

Состояние партии, seed, путь сохранённого отчёта и справка выводятся в `stdout`.
Ошибки и сообщения журнала направляются в `stderr`.

Коды завершения Java-приложения:

| Код | Значение |
|---:|---|
| `0` | Успешное выполнение, справка или версия; сохранённый отчёт может иметь статус `FAILED` |
| `1` | Ошибка записи отчёта или неожиданная ошибка выполнения |
| `2` | Некорректные аргументы или конфигурация |


Отчёты записываются в UTF-8 через временный файл с последующей заменой.
При запуске через Gradle ошибка приложения также приводит к неуспешному выполнению задачи `run`.
